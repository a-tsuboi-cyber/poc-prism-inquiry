## 1. 検証方針と目的

### 1.1. 目的
本システムは、エンドユーザー向けのAI対話・チケット起票と、運用管理者向けのチケット・ナレッジ・ドキュメント管理が密結合したWebプラットフォームです。  
単体テスト（ユニットテスト）では担保しきれない **「ブラウザ上でのユーザー操作・画面描画・API通信・データ永続化（JSONファイル）・外部連携通知（Teams/Gemini）」の一連の動作（End-to-End）を自動検証** し、PRマージ前のリグレッション（先祖返りや不具合）を完全に防ぐことを目的とします。

### 1.2. 採用技術・基盤
- **テストフレームワーク**: [Playwright](https://playwright.dev/) (`@playwright/test`)
- **ブラウザ**: Chromium (Headless モード)
- **テストアーキテクチャ**:
  - `playwright.config.js`: ポート3000上のExpress/Viteサーバーに対する直列実行設定（データ競合防止）
  - `e2e/`: 機能シナリオ別のテストスペック
  - `scripts/run-all-tests.js`: 単体テストとE2Eテストを一括実行する統合ランナー

## 2. テストシナリオ一覧

| シナリオID | 対象機能 | テストシナリオ概要 | 主な検証観点 |
| :--- | :--- | :--- | :--- |
| **E2E-01** | AIチャット & クローズ | 質問送信 → AI回答受領 → 自己解決クローズ | AI回答のMarkdown表示、「解決完了（よかった！）」フィードバックの表示 |
| **E2E-02** | チケットエスカレーション | 解決しない質問 → エスカレーション起票 | AI自動要約の初期値設定、緊急度「高」時の電話番号入力、チケット起票完了 |
| **E2E-03** | マニュアル参照 | ヘッダー「マニュアル」押下 → 一覧・ダウンロード | モーダル表示、公開マニュアル一覧の表示、ダウンロードURL属性の検証 |
| **E2E-04** | チケット管理 | チケット一覧 → 絞り込み → 詳細モーダル → 更新 | 対話ログ再現表示、対応ステータス変更（対応中/完了）と一覧への即時反映 |
| **E2E-05** | ナレッジ昇格 | やり取り一覧 → 推奨ログからナレッジ抽出・登録 | 2ペインモーダル起動、Gemini要約QAの確認、ナレッジ登録実行 |
| **E2E-06** | ナレッジライフサイクル | ナレッジ新規登録 → 編集 → 削除 | Q&Aの新規登録、詳細モーダルでの内容更新、削除確認ダイアログ経由の完全削除 |
| **E2E-07** | ドキュメントライフサイクル | ドキュメント一覧 → タイトル/種別編集 → 削除 | ドキュメント表示名の編集保存、削除確認モーダル経由のファイル/メタデータ削除 |

## 3. テスト実行方法 & CI/PR前運用

### 3.1. E2Eテストの単独実行
開発中や画面動作の集中検証を行う場合：
```powershell
# E2Eテストを実行
npm run test:e2e

# HTMLレポートをブラウザで確認する場合
npx playwright show-report test/reports/playwright-html
```

### 3.2. マージ前・PR作成前の総合テスト (推奨)
単体テスト（58テスト）と E2Eテスト（7シナリオ）を一括実行し、統合Markdownレポートを出力します：
```powershell
npm run test:all
```
- **合格基準**: 単体テスト・E2Eテストともに `FAIL: 0` であること。
- **レポート格納先**: `test/reports/full-test-report-YYYYMMDDHHMMSS.md`
